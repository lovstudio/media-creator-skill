# Screen Studio + Remotion 精剪与验收

这份参考专门约束 `.screenstudio` 源工程进入 Remotion 后最容易“技术上能播、听感却卡”的部分。
它补充通用 EDL、系列模板与音频规则，不替代字幕批准和平台交付门禁。

## 1. 一份剪辑事实，两级媒体缓存

`draft` 只为 EDL 当前引用的区间懒生成 display、webcam、microphone 与 system-audio 的 source-scoped
低码率代理分片；缓存键包含 source revision、channel、源时间范围和 proxy profile，不预转完整长源轨。
本轮把命中分片快速拼成每 channel 一条输出时长的预览轨，后续字幕、布局与 BGM 修改直接复用。
只有画面与对白进入 `locked`，才按 EDL、
语音清理和速度映射生成等长的最终连续四轨；BGM 最后从约定的
`Screen Studio Lo-fi / Bright Lounge` 构建并进入最终混音。平台终版只在 `approved` 后执行。

每轮先运行 `scripts/iteration_plan.py plan`。字幕/布局不重建底层媒体，BGM 不重建视频，平台规格不重做
时间线，封面不触碰音视频。完整失效矩阵和耗时记录见 [`iteration-performance.md`](iteration-performance.md)。

EDL 中至少区分三类删除：

| 类型 | 内容 | 边界门禁 |
| --- | --- | --- |
| `filler` | 独立“啊 / 呃 / 嗯”、无意义拖音 | 两端落在相邻词外的低能量窗 |
| `self-correction` | 口误、未完成起句、说错后重说 | 保留后一次完整表达，不能切掉词头 |
| `editorial-remove` | 用户明确不要的完整解释或冗余段 | 以完整句/完整意群为单位，两端仍需安静 |

不要把三类范围合并成“扩大一点总能删干净”的单表；最危险的事故正是为了删填充音，把完整词或
句尾一起删掉。

## 2. 完整句门禁：draft 局部 ASR + locked 全片 ASR

麦克风先解码为 48kHz PCM。每次改微切点立即执行局部层；进入 `locked` 后再执行全片层：

1. **局部短窗**：切点前后各取足够上下文，确认前句读完、后句从完整词头开始；口误重说只剩
   后一次完整发音。
2. **最终全片**：对连续成片麦克风轨重新转写，扫描独立口水词、重复起句、残缺产品名，以及
   “但是 / 如果 / 所以 / 可以看到”后突然跳段的疑似半句。

点名句、钩子、产品名与结果证据必须同时出现在局部和全片证据里。长窗 ASR 可能把低声词识错，
但若它完全缺少句尾或出现 `Agent Ski… Agent Skill` 一类重启，就不能放行。最终字幕也要检查：
已删除语音不能因时间映射塌缩而残留在切点上。

切点默认使用约 6–8ms 去爆音淡化；更长的淡化会磨掉短辅音。淡化只能处理波形接缝，不能修复
错误的语义边界。

## 3. 开场策略先判别，且不能带编辑痕迹

先检查原始开场是否已经完成钩子职责。第一句或第一个完整意群已经直接说明具体问题、结果、冲突或代价时，
使用 `direct`：从第一句有效语音直接开始，在问题说清之前不插高光蒙太奇、片名卡或特效字幕。需要补充方向感时，
把一张简短的本期内容字幕放在完整问题之后，不放在第 0 帧。原开场偏泛、铺垫长，且后文存在更强闭环时，才使用
`highlights`，由 2–4 个完整短句组成“槽点/冲突 → 升级 → 结果证明”，总长通常 6–15 秒。

两条路径共同遵守：

- 句子从有效语音和有效表情开始，不保留整理表情、等窗口或长静音；
- 槽点可来自字幕中的强否定/反差，也可来自突然加大的音量和重音；两类信号共同排序；
- 结果证明必须说完，例如“可以看到……已经正常播放了”，不能只留前半句；
- 画面不得出现“高光”“高亮”“PROOF”“先看结果”等内部编辑标签；
- 每个钩子单独跑短窗 ASR，并扫首尾静音；弱声不等于静音，需结合波形和转写判断。

SRT cue、用户点名的字幕序号和粗时间码只负责指出“要哪句话”，不负责决定 `src_in/src_out`。
入点从 PCM 中寻找完整词头，删掉语义锚点前多余铺垫；出点必须听到句尾落稳，字幕 cue 先结束时
继续向后扩，不能为了贴时间码把句子截断。最终验收对象是渲染后的冷开场：逐段短窗 ASR、试听并
对照画面切换；源轨切片正确但成片映射错误，同样不得放行。

`highlights` 的片名卡放在高光之后；`direct` 的可选内容字幕放在第一段完整问题之后。正文都不重复录制准备、
试讲或表情整理。用户可用 `auto` / `direct` / `highlights` 覆盖策略，并独立开关或改写问题后字幕。

## 4. 章节、摄像头和动画的连续性

知识传播类默认把章标题卡留 **1.8–2.4 秒**，2.2 秒可作为首轮值；若包含系列名、期号与长标题，
总片名卡仍应更长。章节卡只显示“CHAPTER N / 第 N 章 + 章节标题”，不加解释小标题、承诺句、
预告句或 `kicker`，除非用户明确要求。信息差应由正文展开，不由章节卡提前剧透。

顶部进度导航在任意时刻展示全部宏观章节标题，并区分已完成、当前和未开始；不能只显示当前章。
横竖版共用同一张章节表和累计偏移函数。

摄像头在同一种正文形态中默认连续存在。若一段突然隐藏，必须能由以下理由解释：全屏证据、
隐私遮挡、刻意 B-roll 或独立解释动画。动画只覆盖真正需要可视化的语句；一旦口播重新指向鼠标、
窗口、代码或真实操作，立即恢复屏幕。不得用几十秒动画遮住用户正在操控的画面。

### 4.1 Studio 与最终渲染可能使用不同媒体标签

Remotion Studio 预览中的 `OffthreadVideo` 常由 `<video>` 承载，最终渲染逐帧时可能由 `<img>`
承载。若摄像头 CSS 只命中 `.webcam video`，Studio 会完全正常，编码成片却丢失 `object-fit`、
`object-position` 或尺寸约束，最终只剩脸部极小局部。布局样式应优先落在稳定的 wrapper / class；
必须命中媒体元素时同时覆盖：

```css
.webcam video,
.webcam img {
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

同一规则应用于 `camera-full`、画中画和并排布局。Studio 截图只能证明预览 DOM；平台终版渲染后
必须从最终 MP4 / MKV 抽出各布局代表帧组成联系表，目视检查脸部主体、裁切和定位。只剩胡须、额头、
眼镜或其他异常局部时，按“渲染标签/CSS 未命中”定位，不能归因于源摄像头素材。

### 4.2 竖版平台安全区不是画布安全区

1080×1920 只描述编码画布，不代表整块画面在手机端都可读。视频号全屏播放时，iPhone 的
刘海 / 灵动岛状态栏和微信顶部导航会覆盖画布顶部；把章节栏放在 `top: 20–40px`，即使 Studio
里完全可见，到了真机也会与时间、信号、电量和导航控件重叠。

首轮布局采用以下保守值，再以当前平台实机截图测量结果覆盖：

- 1080×1920 视频号关键内容顶部禁入区：约 `160px`（画布高度的 8.3%）；
- 章节导航、标题、标签、完整网址和关键控件的**墨迹边界**必须全部低于该线；
- 背景、渐变、装饰纹理和非关键视频边缘可以延伸到画布顶端，避免做出突兀黑条；
- 章节栏下移后，正文屏幕舞台从章节栏下沿再留 16–24px 起排；优先压缩舞台空白或重分配
  屏幕 / 摄像头高度，不把内容整体推向底部平台控件；
- `camera-full` 可以铺满画布，但脸、演示结果等视觉主体仍需在安全区内；产品卡、资源页和独立
  解释动画也使用同一关键内容顶边，不能各写一套更小的 `inset-top`。

项目里保留一份 `platformSafeArea`（或等价常量）作为唯一来源，同时驱动章节栏、正文几何和
可开关的调试框。验收至少抽取普通屏幕 + 摄像头、`camera-full`、产品卡、解释动画和资源页各一帧：
先看裸 9:16 静帧，再把当前平台真实 UI 截图叠回去检查。Studio 的虚线框只能证明常量一致，
不能替代真机截图。

## 5. 重点产品官网卡

片中提到重要产品时，尤其是作者或团队自研产品，先以官网为事实源，再做 4.5–5.5 秒的 Remotion
信息卡。卡片至少包含：

- 官网当前主标题或一句真实定位；
- 2–3 个官网可核验要点；
- 完整域名；
- 官方截图或品牌资产；没有合格截图时用品牌资产和克制信息版式，不伪造界面。

卡片通常晚于产品名约 0.25–0.4 秒进入，先让观众听到名字；字幕始终优先可读。卡片结束后回到
真实演示画面。第三方内容另遵守 `pip-research.md` 的版权、真人脸与裁切门禁。

## 6. 片尾资源索引是交付物

口播告别后追加“本期素材与工具”页，列出片中真正出现的产品、仓库、提示词库、素材来源和 BGM：

- 每项同时显示名称与完整 URL；
- BGM 写曲名、来源或授权信息；
- 条目较少时通常保留 6–8 秒，按手机阅读速度增减；
- 资源页期间不再插入未完成口播或表情整理；
- 横竖版都要抽帧检查最长 URL 是否溢出。

资源页不是发布简介的替代品；B 站简介若需要时间轴与链接，仍从最终时间线生成。

## 7. BGM 最后挂载并做连续性扫描

画面、对白、系统声、字幕、章节与资源页全部锁定后，才把已授权的 `Screen Studio Lo-fi / Bright Lounge`
做成与最终时间线等长的单条音乐床。早期程序合成 BGM 已废弃：不得调用前作合成器，也不得在素材缺失时
自动生成替代曲；缺失时记录 `audio_status=blocked-on-agreed-bgm`。
循环连接使用交叉淡化，Remotion 根层只挂载一次。验收至少包括：

- BGM 与时间线时长一致；
- 完整解码无错误；
- `silencedetect` 未发现非设计的内部断点；
- 人声段 ducking 后仍清楚，结果原声优先；
- 改过 EDL 或资源页时，BGM 必须重新生成，不能复用旧时长文件。

最终 ducking、响度和峰值处理完成后，另生成一条与批准母版同源的最终混音供 Studio 主预览使用。
不要让 Studio 主 Composition 再以 `volume=1` 挂低电平原始麦克风轨，并同时拼 system-audio 与 BGM；
这种第二套混音链会让预览与母版听感分叉。原始 stems 可以留在工作区和诊断 Composition，主预览
组件树只能有一个最终混音音频实例。

## 8. Studio 分阶段检查矩阵

Remotion Studio 是画面、节奏、转场、摄像头布局、声音、BGM 和字幕的主预览面。MKV 只在作者
需要 Subtitle Edit 修正字幕时生成，不能替代 Studio 审片。作者返回 SRT 后，保留作者文件不变，
将其导入 Remotion 字幕数据并刷新现有 Studio；批准母版前必须确认 Studio 显示的是该份字幕及最终音频。

`draft` 每轮只跑受影响的开场/切点/布局/字幕/音频窗口和刷新后的 Studio 控制台检查；不机械执行
完整解码、全片 ASR、最终混音或平台抽帧。进入字幕批准或平台渲染前，至少完成：

1. `tsc --noEmit`、Remotion bundle 与 composition discovery；
2. 横版主 Composition；总长不超过 10 分钟时同时发现竖版 Composition；
3. display、webcam、microphone、system-audio、BGM 五轨完整解码和时长回读；
   主预览另确认只挂载一条与批准母版同源的最终混音，并记录其哈希、响度和峰值；
4. `direct` 开场的第一句与问题后标题边界，或 `highlights` 的每一钩；另对每张章节卡、完整句高风险点、产品卡、解释动画前后和资源页定点抽帧；
5. 横竖版都检查章节导航、字幕安全区、产品卡和最长 URL；竖版另外显示平台安全区调试框，并把
   真机顶部状态栏 / 刘海 / 平台导航截图叠回关键帧复核；
6. 对最终连续麦克风轨跑全片 ASR，并对用户点名句保留局部短窗证据；
7. Studio 重新加载后实际播放 8–10 秒，记录帧推进；控制台只统计刷新时间戳之后的新 error/warn；
8. 审片交付时停回主 Composition 第 0 帧，不停止用户正在运行的 Studio 服务；交付报告记录
   Studio URL、主 Composition、字幕 SHA-256 和 BGM 文件名；
9. 平台终版渲染后，从编码文件抽取实际开场分支、`camera-full`、画中画、并排和收尾代表帧，
   生成联系表并目视确认；Studio 截图不得替代这一项。

历史热更新日志不能冒充当前错误；同样，能以 30fps 推进也不能替代完整句与音频连续性检查。
