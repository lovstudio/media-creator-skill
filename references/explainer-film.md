# 讲解片：作者口播、动画证据与成片引用

适用于作者第一人称讲一个产品或 Skill 的讲解片（例如 Skill 介绍片）：作者口播，配动画证据场景，再引用从
已发布成片里截取的片段。叙事骨架仍按 [`media-workflow.md`](media-workflow.md)「叙事骨架」。

规则来自一条 Skill 介绍片的制作过程与作者纠偏：讲本 Skill 怎么剪完一条 13 分钟的转山 vlog；作者口播
重录 5 段、拼成 238.5 秒，竖版成片 278.4 秒先发视频号，再从同一套场景代码派生横版。那部片不是用 Remotion
做的，这里只写与引擎无关的做法；「观测实例」只说明那部片的情况，不作定律。

相关规则在别处，这里只指路：

- 画面上产品的价格、授权与是否开源，以及画面数字与口播数字的口径：[`media-workflow.md`](media-workflow.md)「文案与主题」。
- 口播加配乐的母带：[`audio-mix.md`](audio-mix.md)「通用线性母带」。
- ASR 句界与逐字时间的偏差：[`remotion-pipeline-pitfalls.md`](remotion-pipeline-pitfalls.md)「ASR」。
- 首发画幅已发布、从同一套场景代码派生第二画幅：[`platform-variants.md`](platform-variants.md)「同一条时间线，只换画面与版式」。
- 引用片段的打码：按本片每个画幅的实际裁切逐帧定框，见 [`remotion-pipeline-pitfalls.md`](remotion-pipeline-pitfalls.md)「打码」；
  发布前扫描见 [`delivery-contract.md`](delivery-contract.md)「发布前隐私扫描」。

## 1. 成片片段统一走「成片播放窗」

- 片中凡是展示成片，都套同一个模板，和讲解画面在风格上明确分开，否则观众分不清眼前是讲解动画还是成片。
  作者原话：「涉及到成片展示的，应该要使用统一的模板，以与当前的视频风格区分，否则会让观众困惑」。
- 模板内容：盖满整个画面的深色底、固定位置的播放窗、「成片」标签、片名、该片段在原成片里的时间码，以及
  一行说明。
- 模板由最外层一个共享组件统一绘制；各场景只提供片段来源、起止时间和说明，自己不再画成片视频。对照同一部
  成片的横竖两版时，在同一个模板里并排两个播放窗。
- 成片片段紧跟讲到的那项能力出现，给这项能力作佐证：先讲能力，紧接着放它在成片里的实际效果。
- 建议：交付前给每个成片片段抽一帧拼成联系表，确认都出自这个模板。
- 这个模板是全屏的证据画面，不是产品信息卡：[`screen-studio-remotion-qc.md`](screen-studio-remotion-qc.md)
  「重点产品官网卡」里 4.5–5.5 秒的时长、晚于产品名 0.25–0.4 秒进场的规则不适用于它，
  [`pip-research.md`](pip-research.md) 的画中画贴卡流程也不适用。

## 2. 旁白重录后重新对时

- 作者重录旁白后，按新录音重建时间线：每句的起止用音频本身测，不直接用 ASR 的句界和逐字时间，原因与参数见
  [`remotion-pipeline-pitfalls.md`](remotion-pipeline-pitfalls.md)「ASR」。场景时长按实测的说话起止定。
- 场景画面已按新时间线做好后，才发现某个场景切点切掉了字（两句连读、ASR 句界落在字中间）时，不挪场景窗口、
  不返工画面，只在音频一侧修：把这段音频的取材起止前后挪到完整的字、给接缝处加静音区间或短淡出。
  剪辑数据里音频和画面共用同一组源起止时，先给音频单独记一份修补表，渲染时叠加，不改画面那一侧。
- 字幕和逐字时间以实测的停顿为锚点，锚点之间分段线性映射；字幕手工断句，单条至少显示 0.7 秒。
