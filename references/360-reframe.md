# 360 素材：重投影、取景与复核

适用于双鱼眼全景相机素材重投影成平面镜头，包括从已锁定的竖版派生 16:9。叙事与人物口径见
[`narrative-vlog.md`](narrative-vlog.md)，派生版本的其余流程见 [`platform-variants.md`](platform-variants.md)。
「观测实例」来自冈仁波齐转山 vlog（一台双鱼眼全景相机，终版 60 个 360 镜头），只作观测，不作定律；
换机型或换 ffmpeg 版本要重测。

记号：`yaw` / `pitch` / `roll` 是平面取景窗中心在全景里的方位角、俯仰角和绕视线的旋转（度）；
`hfov` / `vfov` 是取景窗的水平 / 竖直视场（度）。两枚镜头的光轴在拼好的全景里位于 pitch 0°、
yaw 0° 与 yaw 180°。

## 1. 源格式、代理与拼缝

- 先确认双流顺序和视场，不照抄参数。观测实例（Insta360 X4 Air、ffmpeg 9.0）：`.insv` 含两路 3840²
  HEVC，按 `[0:v:1][0:v:0]hstack` 再接 `v360=input=dfisheye:ih_fov=193:iv_fov=193` 拼成全景后，与相机
  同名 LRV 代理的几何一致。换机型先拿同名 LRV 对照确认。
- 联系表、全量转写和取景预览一律读 LRV 这类低清代理；原片只解码渲染用到的区间（观测实例：2 个镜头
  的测试渲染 9 秒）。
- 平面取景窗不跨双鱼眼拼缝。拼缝是离两条光轴都为 90° 的大圆，会从全景的两极穿过，所以要检查取景窗的
  四个角，不能只看水平方向：
  1. 把四角在取景平面上的坐标 `(±tan(hfov/2), ±tan(vfov/2), 1)` 依次按 roll、pitch、yaw 旋转回全景坐标，
     得到每个角的方位角 `yaw_c` 与俯仰角 `pitch_c`；
  2. 选离窗口中心较近的那条光轴，记它的方位角为 `yaw_0`（0° 或 180°），`Δyaw = yaw_c − yaw_0`；
  3. 每个角到这条光轴的角距 `d = arccos(cos pitch_c · cos Δyaw)`，四个角的 `d` 都不超过界限才算安全。
  观测实例的界限是 86°（193° 视场的镜头覆盖到离光轴约 96°，拼缝在 90°，给拼缝留 4°）。取景窗是直线投影，
  四条边都是大圆弧，四角都在界内即整窗在界内。水平近似 `|yaw − yaw_0| + hfov/2 ≤ 86°` 只在 pitch 接近 0、
  vfov 不大时可用；仰拍天空或俯拍脚下时拼缝会从两极穿进画面。近景尤其要守。
- 拼缝错位在低清代理上看不出来，取景定稿前必须用原片抽帧检查。

## 2. 取景流程

- 先出带方位 / 俯仰网格的全景帧定大方向，再按候选参数出每镜多个时刻的预览逐个看。
- 自拍杆素材先确认人物和前进方向各在哪个方位角，写成镜头参数默认值（观测实例：人物在 yaw 150–180°，
  前进方向在 0°）。除口型同步的说话镜头外，默认朝向前进方向、风景或对话对象，不朝作者本人。
- 微调构图优先只动 yaw；改 pitch 前先检查会不会带进路人。
- roll 只用来扶正地平线（几度以内），不要用大角度 roll 去避开画面边缘的东西。观测实例：roll −56° 时
  眼位掉到画面 55–60% 高度，整幅歪斜。
- 1920 宽输出里 hfov 以 60–100° 为起点，最多 105°（再宽直线投影边缘拉伸明显）。视场越窄，源像素被放大得
  越多；想“推近”就换更近的镜头或素材。改窄视场时拼缝仍按上一节四角重算。观测实例：两版 hfov 50° 的镜头
  在全分辨率下明显发软，只剩岩壁局部。

## 3. 对话场景：先认人，再定机位

- 作者要求“给对方镜头”时，先出整张全景帧，按座位朝向、说话内容、口型和手势确认对话对象——回答的
  人，不是离镜头近或容易取景的人。每位说话人各定一个 yaw 机位，谁说话或被问就切给谁。
- 避让旁人时只能在对话对象附近调整取景，不能因此换拍别的人。观测实例：两次按离镜头近、好取景的人定
  机位，选中的都是旁边站着的路人，作者两次纠正；最后在全景里找到对面坐着的两位（约 ±25°）。
- 改完从 Studio 或成片按作者给的时间点截帧，确认新机位已经生效再回复。

## 4. 整段复核与防抖

- 定参后至少每 0.5 秒抽帧复核整条使用区间（含叠化尾巴）：人物是否走出画面、手持晃动是否把主体甩出、
  有没有不该入镜的人（这是取景阶段的复核；发布前的全片隐私扫描另按 delivery-contract「发布前隐私扫描」）。
  晃动或走位点前后拆成两个机位（观测实例：以 8.8 秒为界拆开；只看起点帧的一版
  后 3 秒两人走出画面，只剩冰柜）。
- 复核通过的 yaw / pitch / hfov 视为锁定；放宽视角等于换了新取景，必须重新复核。
- 手持 360 重投影后发晃：用两遍 vidstab（先检测再变换，带 optzoom），平滑强度取中等值（约 20），
  视角先放宽约 10–12° 给裁边留余量。平滑太强会抵消有意的慢转，把主体推出画面（观测实例：平滑 40
  时人物出框，8 几乎无效）。用相位相关的逐帧位移量化效果（观测实例：平均位移约 3 px 降到 1 px 以内，
  最大甩动 19 px 降到 5.4 px），再抽帧确认主体始终在框内。

## 5. 镜头内运镜

- 要从当前主体揭示远处地标时，用镜头内缓动运镜（yaw、pitch、hfov 用 smoothstep 从起点插值到终点），
  比硬切自然。起点和终点都要按第 1 节查拼缝和近景变形；拼缝检查只覆盖起点时，终点全分辨率放大人工核对。
- ffmpeg 9 的 `v360` 用 `sendcmd` 驱动时，`yaw` / `pitch` 命令是增量（每帧发与上一帧的差值），
  `h_fov` / `v_fov` 是绝对值。换 ffmpeg 版本先用“连续发几条相同命令”的小实验确认语义再批量渲染。
- 带运镜的镜头一律用与成片相同的逐帧 sendcmd 路径出联系表验证，不用“一次跳到终点”的单帧预览；
  roll ≠ 0 时两者结果不同。观测实例：同一时刻电线杆位置差约 470 px，真实终点把拼缝带进了右缘。
  终点附近每 0.25 秒放大一次画面边缘查拼缝。

## 6. 派生 16:9

- 时间码、混音、字幕沿用锁定时间线，每个 360 镜头重投影，不裁竖版画面。保持竖版 yaw / pitch，按主体
  像素大小相同换算横版视场 `hfov_h = 2·atan(tan(hfov_v/2)·16/9)`，其中 `hfov_v` 是该镜头竖版取景的
  水平视场；默认上限 100°、最大 105°，再逐镜头覆盖参数。
- 竖版安全不代表横版安全。联系表覆盖每个镜头的全部使用区间，用线标出竖版画面的左右边界，逐格查线外
  新露出的内容：他人、作者自己的腿脚和自拍杆、拼缝、车牌和二维码；手持甩动的瞬间单独放大边缘。
- 说话或自拍镜头：横版竖向视场小，按默认换算脸常被切到底边，或头顶贴上缘。逐镜头调 pitch，额头和
  下巴都完整，眼睛落在画面上三分之一到中线之间；用人脸检测实测眼位分布，不信取景方写的数字。脸在横版
  里不明显大于竖版（约 1.2 倍以内），超出就在镜头备注写明取舍。
- 风景镜头：重看地平线位置和天地比例，保留竖版的兴趣中心，不直接照搬 pitch；有字幕的长镜头避免
  半屏路面或整屏空天。
- 宿主允许子 agent 时，批量重取景可用“取景 agent + 独立复核员”配对，见
  [`iteration-performance.md`](iteration-performance.md)「多 agent 批量复核」。
