# 系列片模板标准

一个系列的第二期不该从零开始。这份文件记的是**每期都要过一遍的成片标准**，来源是
《手工川与你一起学 DeepSeek Harness》EP.01 定型、EP.02 被退回一次后补齐的那一套。
Screen Studio + Remotion 项目还要逐条执行 [`screen-studio-remotion-qc.md`](screen-studio-remotion-qc.md)。

## 系列名的两个形态

| 形态 | 文本 | 用在哪 |
| --- | --- | --- |
| 全称 | 手工川与你一起学 DeepSeek Harness | 封面第二行（锚点条）、片名卡、B 站等不限字数的合集名、正文文案 |
| 短名 | 手工川DSH实战 | **只在平台有字数上限时用**（视频号合集限 10 字，这个 7 字刚好） |

短名是用户给定的既有资产，不是现场缩的。撞到字数限制时用它，不要自己截断全称、也不要
临时另起一个名——合集名在视频号**创建后不可修改**，起错会跟着整个系列。

**「撞上限」要先证实，再降级用短名。** 同一平台的创建表单和编辑表单上限可能不同：B 站
创建合集的弹窗限 20 字（全称 25 字进不去），但「编辑合集」表单限 50 字，先建再改名就能用全称。
2026-08-18 我在这里直接按创建弹窗的 20 字换了短名，被用户退回——**默认是全称，短名要有实证**。
判据：读到 `input.maxLength` 和 `n/N` 计数器，两个表单各读一次。

写这份文件的直接原因：EP.02 初剪只做了「删大空档 + 烧字幕 + 章标」就交付，被判定为
「非常粗糙的初剪」。EP.01 的规范当时只存在于那个仓库的代码里，新一期不去读代码就等于
重新发明一遍——**规范不进 Skill，就等于没有规范。**

## 进度条画的是幕，不是细章节：两个颗粒度，一张表

**顶栏的颗粒度上限是 10 幕，下限是 3 幕。** 这不是美学偏好，是可读性：条子只有 ~1660px，
标签 19px，一条 6 字标签约 116px，10 条加间隙就到 1200px；再多就必须把名字缩回两个字，
而两个字算不上名字。EP.03 先按「显示全部章节结构」画了 21 条细章节，排得下（1038/1660px），
标签也全落下了，验收仍然被判**颗粒度太细**——20 分钟片子平均每节 58s，观众看到的是一排
读不出结构的碎片。

细章节不要删，它们另有两个用处：剪辑节奏（章节交界的气口留 0.40s 而不是 0.14s）和
B 站简介里可跳转的目录。所以是**两个颗粒度、一张分组表**：

- 分幕表以“从第几条细章节开始”（索引）定义语义归属，不另抄一份手写时间。幕标题卡默认就放
  在该起点；如果起点切进一句话，可另记一个 `card_at` 展示点，但它必须吸附到相邻口播句界或
  EDL 片段边界，并在报告记录偏移。语义起点仍由细章节索引决定。
- 分组规则写死成数据，**不是「取前 N 个」**——取前 N 个会让整片后半段在顶栏上彻底消失。
- 断言写在表旁边：幕数落在 3–10、第一幕索引为 0、索引严格递增且不越界。
- **顶栏和发布文案读同一张表。** 视频号描述里的大节点曾经是发布脚本里另一张分组表，
  和顶栏各维护一份，必然漂移；删掉那张，两边都读分幕表。
- 每个幕对象多存一条 `summary_evidence`，用该幕真实口播/画面说明为什么叫这个名字。命名先问
  “这一幕具体在解释或证明什么”，再压成短标题；禁止拿参与方式、制作动作或抽象气氛当主题。
- 幕继承细章节的 `src`/`at`，但两边都有 `title`——**合并顺序反了就会静默取错名字**
  （`dict(act, **chapter)` 让细章节名覆盖幕名，顶栏因为读 `bar` 键仍然正确，只有交付
  文案里的幕名悄悄变成细章节名）。写成 `dict(chapter, **act)`。

8 幕腾出来的宽度刚好放幕的真名（4–6 字），不必再做两级命名。

## 章标题要说内容；黑幕卡要真正占时间

章标题不是剪辑动作标签。像“参与开源”只说明创作者做了什么，不能概括一段“为什么开始用、
发现什么问题、第一次 PR 如何发生”的内容，标题应落到“背景”；同理，一段在用 Typeless 样本
反推并发布自定义模式，核心是“自定义 Prompt”，不是泛化的“共创风格”。

每张启用的卡用同一份分幕数据渲染两行：上行为“第一章 / 第二章……”，下行为语义标题。卡片必须作为
独立片段插入时间线，不能直接盖住正在播放的录屏，否则会遮掉操作证据、让口播在黑幕下继续，
也会制造字幕缺口。实现时把正文切在 `card_at` 边界，顺序由开场分支决定：

```text
highlights：高光 → 总片名卡 → 可选第一章卡 → 第一章正文 → 第二章卡 → … → 片尾
direct：第一章正文开场 → 可选问题后标题 → 第一章正文续段 → 第二章卡 → … → 片尾
```

音频在卡片时长内不给旁白采样；低声 BGM 可连续，章切点可放一个稀释后的 whoosh。字幕起点、
终点、重点词音效、画中画、细章节与发布时码都使用同一个累计偏移函数：对正文时间 `t`，加上
所有 `card_at <= t` 的卡片帧数。cue 终点恰好等于卡片起点时不加该卡，cue 起点相等时要加，
并对“没有任何 cue 跨过 card_at”下断言。SRT 只有毫秒精度：从帧时间换算时，cue 起点向上取整、
终点向下取整；否则 60fps 的 16.083333s 会被四舍五入到 16.083s，产生肉眼看不见但结构真实的
0.333ms 卡片交叠。

## 剪辑节奏：气口不是重点，死气才是

用户会说「剪掉语气词」，但实测下来那些词只占极小部分。EP.02 的账：

| 处置 | 量 |
| --- | --- |
| 语气词整句丢弃 | 15 处 / 5.7s |
| 句尾拖音剪掉 | 18 处 / 3.3s |
| **静止停顿剪到 0.14s** | 331 处 / 省下 45.4s |
| **有动作的停顿抽帧到 ~1/3** | 371 处 |

语气词值 9.0s，而**没人说话、屏幕也没动**的死气值 216s。所以检测器不能只枚举
「≥1.2s 的大空档」，要用 10ms 粒度扫整条语音包络。

拼接密度上去之后（EP.02 有 703 处人声拼接），淡入淡出要跟着缩短：**30ms 降到 6ms**，
否则短句的首尾辅音会被斜坡磨掉。前提是每个切点已吸附到附近最静的 10ms 窗口。

## 声音三件事

1. **配乐使用约定曲目。** 固定使用已授权的 `Screen Studio Lo-fi / Bright Lounge`；早期程序合成器、
   `make_music.py` 和同类生成脚本全部废弃，不 import、不复制、不作为缺失素材的回退方案。
2. **动态跟着画面走。** 通过音量自动化、ducking 与必要的段落淡化控制密度，不改写或重新生成曲目。
3. **音效要稀释。** 重点词提示音按「每 N 秒最多一次」筛，不是每处都响——每处都响是节拍器。

配乐大约压到比人声低 15 dB，配合侧链避让（人声一来就让位）；停顿处让它完全打开，
这样「删掉的气口」听起来是干净而不是断了。

## 钩子边界按包络定，不按转写定

转写给的 cue 边界会切在音节中间。做法是抽 10ms 包络，找到这句话前面的真静音起点和
后面那个低谷，用实测值定 `-ss` / `-t`。钩子长度因此可能是 2.55s 这种非整数——
**长度跟着句子走，不要凑整。**

用户点名 cue 时把它当语义锚点：开头多出来的铺垫可以从 PCM 入点修掉，但完整词头必须保留；
cue 结尾早于句尾时必须向后扩到整句落稳。定边界后再检查实际渲染冷开场，不能只试听源轨切片。

## 渲染层面的坑

- **overlay 的字幕底板不能靠行内改色做强调。** libass 给每个样式段各画一块底板，行内
  改色等于第二块底板压在第一块上，重叠处 alpha 叠加变深。做法是**同一行画两遍**：
  第一遍整行常规色出一块完整底板，第二遍关掉底板、把非重点字设为全透明，只留重点词
  浮在上面。两遍同样式同文本才会落在同一像素上（所以强调不能加粗——字重变了就会错位）。
- **底板不透明度 ≥90%。** EP.03 用了 45%（`&H8C…`），压在浅色模式的网页上被提亮到
  亮度 ~145，而陶土色文字是 ~141——章节名和进度条标签**完全读不出来**。底板的作用是
  隔断背景，不是修饰；浅底素材上它必须近乎不透明（`&H1A…`）。这条只能靠抽帧看图发现，
  任何数值门禁都查不出来。
- **EDL 段之间不许有重叠帧。** 取整是分别做的，短停顿的保留头很容易越过停顿末帧、
  和下一段人声重叠一帧。而 `select` 对被两次声明的帧只保留一次，于是**下游所有帧数都是
  假的**，报错出现在渲染完之后。加一条全局断言 `next.f_in >= prev.f_out`。
- **前作的几何常量不可照抄，必须逐帧量。** EP.02 的 `crop=1660:991:0:38` 拿到 EP.03
  会毁掉 **99.5%** 的帧——34% 的素材是全屏 App，页签起于 `y=8`。EP.03 最后只用
  `pad=1920:1080:130:0:black`（1.0x、零重采样），比 EP.02 那版 1.03x 上采样更清楚。
- **覆盖层的改动无法补渲。** 每个分块都带覆盖层，所以改字幕**样式**等于全量重渲；
  只改单条字幕的文字才能精确补渲那几个分块。改样式前先渲一个分块做校样，别直接开全量。
- **改完 `subs.ass` 必须重跑分块切分脚本再渲。** 分块渲染的滤镜链读的是切出来的
  per-chunk `s_NN.ass`，不是 `subs.ass` 本身。少跑这一步，渲染全程零报错，出来的却是
  上一版覆盖层——而校样图看起来完全正常，因为它确实是「某一版」成片。链条是
  `build_subs.py` → `make_chunks.py` → `render.py`，中间那一步不能跳。
- **改完覆盖层先确认 EDL 有没有动。** 没动（`edit-manifest.json` 逐键与上一版一致）就只重渲
  画面，音频整条复用，不必重跑混音与响度；动了就整条音频链按顺序全部重跑。
- **一个分块不许跨素材。** 多素材剪辑时 chunk 的 `-ss` 与 `select` 帧号只对自己那个
  输入文件有意义，跨了会静默渲错素材。分组时同时按容量和 `src` 断开，并对每组下断言：

  ```python
  if run and (len(run) >= PER_CHUNK or run[-1]['src'] != s['src']):
      chunks.append(run); run = []
  ...
  assert all(s['src'] == src for s in grp), '一个分块跨了两个素材'
  ```

- **成片帧数从盘上回读，不从计划里抄。** `finalize()` 逐个 clip 重新 `ffprobe` 帧数
  再对总数下断言（EP.03：61 段共 73875 帧 = 正片 72863 + 片头片尾 1012）。
- **Studio 的媒体标签不能代表最终渲染。** `OffthreadVideo` 在 Studio 中可能是 `<video>`，
  最终渲染帧可能是 `<img>`；摄像头裁切样式只写 `.webcam video` 会导致预览正常、成片只剩
  胡须等局部。样式落在稳定 wrapper，或同时覆盖 `video, img`；终版后从编码文件抽各摄像头布局
  联系表目视检查，不能拿 Studio 截图替代。
- 横版舞台按宽度装会溢出画布，必须按 `canvas_h - rail_h` 反推宽（2026-09-05, 44885a9）
- 字幕用 `left:50%+translateX(-50%)` 时包含块只有半幅宽、`max-width` 失效会断词，改 `left:0;right:0;margin:0 auto;width:fit-content`（2026-09-05, 44885a9）
- 摄像头卡与源同宽高比时 `object-fit:cover` 等于不裁，推近必须自己写 `transform:scale()`（2026-09-05, 44885a9）
- 单遍 `loudnorm` 偏 2–3 LU，响度归一要在最终混音上做两遍并回读 `ebur128`（2026-09-05, 44885a9）（2026-09-29 起：第二遍必须是 `normalization_type: linear`，退回 dynamic 时改走 audio-mix「通用线性母带」）
- `whisper-cli` 的 `-ml 1 -sow` 对中文不切词，词级时间戳只能用 `-dtw large.v3.turbo -ojf`（2026-09-05, 44885a9）
- 新版 ffmpeg 已移除 `-vsync`，逐帧抽帧改用 `-fps_mode passthrough`（2026-09-05, 44885a9）
- 源片两端断在句中时先做可用性判定再开工，不足一句完整话的素材只能交微片段（2026-09-05, 44885a9）

## 片尾资源卡：地址栏靠 OCR 抠，判据有四条

硬性清单第 3 条要求「一帧列出全部参考资源」。演示片里这些地址只存在于**浏览器地址栏**，
字幕里读不到，所以按低帧率抽帧、裁出地址栏 band 跑 tesseract。四条判据都是踩出来的：

- **`--psm 12` 与 `--psm 6` 取并集。** band 其实是**两行** UI（页签 + 地址栏），
  单行模式 `--psm 7` 在 1106 帧上是**零命中**。
- **域名匹配按长度降序，前缀剥离条件是 `i >= 0` 不是 `i > 0`。** 两个 bug 叠起来会把
  `platform.deepseek.com/api_keys` 截成 `deepseek.com/api_keys`——一个**不存在的页面**，
  而且看不出是错的。

  ```python
  DOMAINS = sorted(KNOWN_DOMAINS, key=len, reverse=True)
  for d in DOMAINS:
      i = t.find(d)
      if i >= 0:                  # i > 0 会漏掉「整行就是这个域名」的情况
          t = t[i:]; break
  ```

- **判「这行是不是地址栏」用去掉 URL 后剩余的英文单词数（≤3）。** 页面正文里也有 URL：
  EP.03 差点把 GUI 自己 system prompt 里写的 `127.0.0.1:2080` 当成访问过的资源，
  而地址栏上写的是 3080。
- **原始 OCR 文本落盘缓存。** 判据要反复改，重跑 tesseract 每次 5 分钟。

字形歧义（`0`/`O`、`1`/`l`）放大像素也读不出来，去问权威接口：`0xsline/…` 返回 200、
`Oxsline/…` 返回 404，这才是证据。最后对「有 URL 但没有显示名」的条目下断言，
逼自己把每条都命名；屏上出现过但不在地址栏的资源（口播提到的）单独列一张表补进去。

资源卡的排版要按**字符宽度**下断言，不要目测字号：

```python
URL_EM = 0.6 * FONT_PX
assert len(r['url']) * URL_EM <= room, (r['url'], room)
```

## 竖版 / 横版的选择不是一次性决定

系列风格一致是默认，但**素材可以否掉它**。判据是屏上文字：

- 口播为主、屏上没有需要读的字 → 竖版没问题；
- 演示为主、内容就是屏幕上的英文/代码/地址栏 → 竖版把画面压到 0.65x 之后那些字就废了，
  这时候出横版一刀是对的。

不要用「上一期是竖版」直接推导本期，也不要用「技术上装不下」直接推翻系列一致——
**先做一版让用户看，再定。**

## 交付时间码必须由脚本生成

改片头长度是**静默破坏**：EP.02 把冷开场从 2.55s 扩到 9.883s、片名卡 1.60s → 2.800s，
正片一帧没动，但 `body_out_start` 从 4.15s 移到 12.683s——发布文案、交付报告、章节表、
资源表里 13 + 17 共 **30 个时间码同时变成假的，而没有任何东西会报错**。观众按时间码
拖进度条才会发现，那时已经发出去了。

做法是写一个本期的生成脚本（EP.02 是 `output/work/ep02/timeline_check.py`）：

```python
SEG = [s for s in MAN['segments'] if s['n_out'] > 0]
CUM, _t = [], 0
for s in SEG:
    CUM.append(_t); _t += s['n_out']
assert _t == MAN['total_out_frames']

def film_time(src):                      # 源秒 -> 成片秒
    for c, s in zip(CUM, SEG):
        if src < s['src_out']:
            if src <= s['src_in']:
                return START + c / FPS
            frac = (src - s['src_in']) / (s['src_out'] - s['src_in'])
            return START + (c + frac * s['n_out']) / FPS
```

`START = bookends.json['body_out_start']`。脚本最后对总帧数和 ffprobe 回读各下一条断言。
**验证映射本身的办法**：用上一版的 `body_out_start` 跑一遍，必须精确复现上一版的全部数字，
复现不了就是映射写错了，不是上一版抄错了。

改了片头/片尾长度之后，先跑生成脚本，文档里的时间码一律从生成的 JSON 抄。

**再进一步：整份交付报告都该由脚本生成，不只是时间码。** EP.03 的手写报告在改完钩子长度和
片名卡之后，有 18 行数字同时失效——帧数、时长、文件大小、剪除率、章节数、字幕条数、
封面门禁分数，全都是成片时间轴的函数。危险的地方在于**报告读起来依然自洽**：它内部没有
矛盾，只是和成片对不上，没有任何门禁会发现。

做法（EP.03 是 `output/work/ep03/make_report.py`）：叙述仍然是人写的，但每一个数字都从
交付 JSON 插值，脚本里不允许出现第二份字面量。附带两个好处：

- **质检结论不许写死。** 解码检查的结果从 `decode-check.txt` 读，文件不存在就在报告里印
  「未跑」，而不是默认印「零错误」——报告不能替质检打绿灯。
- 「已渲 / 已质检 / 已提交 / 已回读」四个状态各自从对应产物推导，谁没跑就显示谁没跑。

## 响度：折混高 3 dB 只对峰值是假象，对 LUFS 是真的

这两件事长得一样，结论相反，EP.02 就是在这里栽的。

**峰值**：`ffmpeg -f f32le -ac 1` 的立体声下混是等能量的（每声道 ×1/√2），dual-mono
母版折混后正好高 3.01 dB。EP.02 母版真峰 −0.41 dBFS，折混后被报成 **+2.58 dBFS**，
凭空报出削顶。查真实削顶只能两声道分开统计 `|x| > 1.0` 的采样数。

**响度**：BS.1770-4 **对各声道的加权能量求和**，所以那 3 dB 不是假象。
`integrated_lufs(y.mean(axis=1))` 这种「先折混再测」的写法比标准表**低 3 dB**，
按它解增益，交付出来就比标称响 3 dB：

| | 混音脚本自报 | ffmpeg `ebur128` 实测 |
| --- | --- | --- |
| EP.01 | −16.9 | −16.9 |
| EP.02 | −16.0 | **−13.0** |
| EP.03 | −16.0 | −16.0 |

EP.02 报告里写着 −16.00，实际交付 −13.0，比 EP.01 响 3.9 dB，两期之间用户会听出来。
所以：**解增益的表和验收的表必须是同一口径**，且都要按声道求和。

```python
def integrated_lufs_stereo(y, sr=48000):          # y.shape == (n, 2)
    blk = int(0.400 * sr)
    ms = sum(_block_ms(k_weight(y[:, ch]), blk, blk // 4) for ch in range(y.shape[1]))
    ...                                            # 门限照 BS.1770-4 走
```

块能量用累积和写（`cumsum` 差分），不要建块索引矩阵——400ms 块 / 100ms 跳步在
20 分钟片上是 3 亿个索引，一次 solver 调用就要 2.4 GB。

**交付后必须用 `ffmpeg -af ebur128` 复核成片本身**，并在脚本里对两个数下断言
（EP.03 用 `abs(delivered - mixed) < 0.6`）。混音脚本自报的数不是交付事实。

## 限幅顶要给 AAC 留余量

AAC 编码会抬高内插真峰约 **0.5 dB**。限幅顶设 −1.5 dBFS 时，EP.03 交付实测真峰
恰好 **−1.0 dBTP**——正好压在契约线上，等于没有余量。顶改到 **−2.0 dBFS** 后交付
−1.5 dBTP。

好在这一步只需重做母版和 remux，画面不用重渲。

## 语音清理：两个判据都不能按直觉写

- **停顿要不要剪，看运动帧占比，不看运动量中位数。** agent 的流式输出是突发的：
  EP.03 有一段 110.8s，逐帧运动量中位数只有 0.0075（看着像静止），但 **27.9% 的帧在动**。
  按中位数判就会把正在输出的屏幕剪成静帧。EP.03 另有 11 段纯等待（源 338.2s → 成片 42.4s，
  最长一段源 183s），这类段落单独归类写进报告，不要和讲解段一起平均。
- **音节密度按音节算，不按字符算。** CJK 记 1、拉丁记 0.4。按字符算的话
  `system prompt` 这种真实字幕（14 字符 / 短音频）会被当成幻觉丢掉。

## whisper 会凭空生成整句，必须三层过滤

EP.03 从转写里筛出 **150 条**幻觉，包括一句「打赏支持」打在**超过文件长度**的时间点上，
以及同一句被解出 **131 次**。不过滤就直接烧进画面。三层判据：

1. 该 cue 时间窗内的**有声秒数**（无声段的整句直接丢）；
2. **音节密度**（音节数 / 时长，上下限都要卡）；
3. **窗口内重复频次**（同文本在邻近窗口反复出现即为解码循环）。


## Studio 是主预览；MKV 只用于字幕修正，批准 SRT 才是最终权威源

烧进画面的字幕不等于用户能校对的字幕。ASR 的错字、断句和时间边界往往只有作者能判断，
所以每期先把画面、声音、BGM 与当前字幕放进 Remotion Studio 预览。只有作者需要 Subtitle Edit
修正时，才交 `review-vN.mkv + review-vN.srt`：MKV 里的旁白字幕是 SubRip 软轨，画面母版本身
不烧旁白字幕；外置 SRT 让 Subtitle Edit 不必先抽轨。MKV 不承担画面审片。

- **导出时不要把注释写进 SRT**：播放器会把它当第二行字幕显示。
- **审校版不是成片**：状态固定为 `subtitle_status=awaiting-review`，批准前不生成平台 MP4。
- **作者可以改文字、合并/拆分 cue 和时间码**。改完的 UTF-8 SRT 成为唯一权威字幕源；不要再把
  它按序号或 `SequenceMatcher` 猜测性灌回旧 cue JSON，也不要丢弃作者修改过的时间码；应直接按
  SRT 时间码导入新的 Remotion 字幕数据，刷新 Studio 并复核。
- **批准门禁检查结构，不改作者决定**：序号可重排，但时间必须递增、正时长、无重叠、不能超出
  成片边界；内嵌后再抽轨，与批准 SRT 逐条比对。
- **只有用户明确确认才批准**：将批准 SRT 的 SHA-256 和确认时间写入报告，再以 stream copy 替换
  审校 MKV 的字幕轨，得到 `master-vN.mkv`。

平台文件从批准后的字幕派生：B 站优先 MP4 + 平台 CC；视频号等不承诺保留内嵌字幕轨的平台，
用批准 SRT 烧录一次 MP4。容器能上传，不代表平台会保留软字幕轨。

## 顶部章节带：不能裁的时候就画，但带高要量出来

前作裁掉菜单栏得到一条真黑带，可以往里放东西。这一期不能裁（34% 的帧是从 y=8 起画的全屏
应用），于是带子只能是一块盖在画面上的不透明底板。带高必须量，不能挑：

- 扫两条素材的行亮度 + 逐行水平边缘能量（0.1fps 就够）。窗口态 y=0..38 是 macOS 菜单栏
  （深色，边缘能量 6.96，那能量就是菜单文字），全屏态那一段是页面白；紧下面 y=39..47 是
  0.23，即空的。所以 39 是精确边界。
- **多一行就开始吃标签栏**，留下半截红绿灯，比不盖更难看。
- 地址栏在 y=60..200（两种窗口态都在这个范围），而这一期地址栏是内容，带子绝不能碰到。
- **要底板就给满，不要半透明。** 92% 的近黑板压在白色菜单栏上，白字会透出来读成一层脏；
  同一块板压在浅色网页上，页面正文会透到标题背后（EP.03 实拍：左下块上透出
  「…to access our AI models, dev…」）。我先前只改了顶带，给左下块留了 92%，理由写的是
  「它压在深色 UI 上」——**那是对素材的假设，而不是对这一帧的测量**。演示片会切到浅色网页、
  白底文档、搜索结果页，任何「背景应该是深的」的前提都会在某一帧失效。
- **顶带要底板，左下身份块不要。** 顶带盖的是菜单栏，那本来就不是内容；身份块坐在画面里，
  一块常驻不变的底板既是过度强调，又会吃掉底下的画面——EP.03 给满之后它盖掉了录屏里
  macOS dock 左端三个图标。身份块改成纯文本加描边，见下一节。

## 左下身份块：三面墙都要量出来，并写成断言

身份块常驻全片，它的位置是被三面墙夹出来的，不是留白偏好。EP.03 第一版凭目测放，结果压住
了录屏里 macOS 的 dock，验收判「离边缘太近，不友好」。三面墙分别是：

- **上：字幕底板的下沿。** 在黑底上烧一遍字幕 ASS 直接量
  （`ffmpeg -f lavfi -i color=c=black:s=1920x1080 -vf "setpts=PTS+{t}/TB,ass=subs.ass"`），
  **扫的 x 范围要排掉其它覆盖层**，否则量到的是身份块自己。对齐方式 2 配 `MarginV` 是从
  底部定位的，多行字幕只往上长，所以这条下沿是稳定的（EP.03：919）。
- **下：录屏里 dock 的上沿。** 逐帧扫 **亮度台阶**——列平均亮度自底向上第一个 >200 的行，
  x 限在 40..640。**不要用饱和度扫**：应用自己的彩色图标同样饱和，量出来的边界会在
  860–1032 之间乱跳。dock 位置固定，只会被窗口盖住、不会移动，所以取各素材的最小值
  （EP.03：素材2 稳定 1012，素材1 最靠上 1010 → 取 1010）。
- **左：画面左缘**（有 pad 时是 pad 后的画面边，不是帧边），留够内缩。

两条墙之间常常只剩几十像素（EP.03 是 90px 装两行），行距要从前作收一点，让上下净距都还
看得见；**不要从两面墙里借**。三面墙都写成断言，因为它们是测量值，会过期：换个 dock 尺寸
重录，或改一次字幕 `MarginV`，这块就会重新盖住东西而没人报错。

**改描边宽度就要重量。** 描边往外长，2.8→3.4px 会让墨迹各向外推 1px，而离 dock 可能只剩
8px。断言里的「anchor 到墨迹边缘」偏移量必须跟着重测。

**没有底板时配色要相对字幕反过来：深字 + 近白描边。** 字幕能保持浅字是因为它自带底板；
身份块直接坐在录屏上，配色由**录屏的主题**决定。EP.03 通篇浅色 UI，近白字配深描边时系列名
在应用白底上几乎读不出，还和它压到的状态栏文字打架；换成陶土色标题 + 暖深灰系列名压近白
描边就干净，偶尔切到深色帧也仍然读得出（描边勾出字形，不靠填充色区分）。**这个判断绑在
浅色录屏上，下一期若是深色模式必须在真实帧上重新校样，不能照抄。** 一律抽帧看图，
任何数值门禁都查不出来。

代价要接受：没有底板时，画面里恰好落在同一基线的浅色文字（EP.03 是应用自己的「设置」）会
从描边缝隙里透一点。字本身清楚，为这个重渲不值。

## 章节标签要排两遍，并用真实字体测宽

标签数量多、段宽不均时（21 章、最窄段只有几十像素），做法是让标签脱离自己那一段的中心：
从左到右跑一遍，撞车就往右挪；**再从右往左跑一遍把尾巴收回画面内**。只做第一遍会把挤压
累积到右边界，最后一个标签落在画面外 20px。只有两遍都跑完还撞，才是真的排不下。

宽度用 PIL 按真实字号测（`ImageFont.truetype` + `textlength`），不要用「CJK 19px / 拉丁
9.5px」这类逐字估算——估算和实际差得足够藏住那 20px 溢出，断言会假通过。

前作把「哪些标签放得下」当成筛选条件、放不下就丢掉的做法是错的：那会白扔掉 5 个章名，而
两遍排布之后 21 个全放得下。

## 切掉工具自身出故障的片段：只有静音才安全

节奏规则不会删有画面动作的停顿，因为演示片里动作就是内容。它看不见的例外是：动作本身是
**工具坏了**（撞上 bug、点重新加载、页面白屏重载）。这种段落要整段切除，不是抽帧。

判据只有一条：**那段必须是静音**。EP.03 那一段实测 121.5–130.9s 全程 −94 dBFS（底噪），
语音在 121.4 结束、131.0 恢复，所以切掉不影响脚本与音频连续性。写进代码要带断言
（`assert loud <= TH_DB`），一个吃掉人声的切除范围必须让脚本失败而不是让成片失声。

另外，被切除留下的空档**不是气口**，不要再交给停顿处理去「压缩」——那里什么都没有了。

## 改了 EDL，音频链要按顺序全部重跑

依赖顺序是 `plan.py → bookends.py → make_audio.py → prepare_bgm_bed.py → mix_film.py`，
每一步都读上一步的产物，而且**都不检查上游是否比自己新**。踩过两次：

- 改 EXCISE 之后只重跑了 plan，`audio_edit.wav` 还是旧的——声画会整体错开。
- 重渲片头三镜改变了全片帧数，而音乐床构建仍读旧 `bookends.json`；在 bookends 之前
  构建 BGM 床，产物会保持上一版长度（73875 帧的乐，配 73717 帧的片）。`prepare_bgm_bed.py`
  只允许循环、交叉淡化、裁切与响度预处理约定曲目，不得合成新音乐。

开工前对一遍文件时间戳，比事后从成片里听出来便宜得多。

## 本期文案只准有一份：`episode.py`

EP.03 改标题时踩过一次：同一个「本期标题」在四个脚本里各存了一份字面量——
`build_subs.py`（左下身份块）、`publish_copy.py`（发布文案）、`make_cover.py`（封面钩子）、
`bookends.py`（片名卡）。改了前三份、漏了片名卡，于是**成片开头还在念旧标题，而所有门禁
都是绿的**：没有任何一处会比较两份字符串是否一致，抽帧也只会抽到你正在改的那处。

所以每期开工先建 `output/work/epNN/episode.py`，只写一次：

```python
BRAND, PROGRAM, EP = '手工川与你一起学', 'DeepSeek Harness', '03'
TITLE = '本期标题'
SERIES     = f'{BRAND} {PROGRAM}'        # 系列名
SERIES_EP  = f'{SERIES} · EP.{EP}'       # 带期号
CARD_SUB   = f'EP.{EP} · {TITLE}'        # 片名卡第三行
END_LINE   = f'{SERIES_EP} · {SITE}'     # 片尾署名行
```

各脚本 `import episode as E` 取用。脚本都是从仓库根以 `python3 output/work/epNN/xxx.py`
启动的，`sys.path[0]` 就是脚本目录，不需要动 `sys.path`。

收口之后加一条自检：`grep -rn "<本期标题>" output/work/epNN/*.py` 只应命中 `episode.py`
和注释。**用户改一次标题就要动四个文件，这件事本身就是缺陷**，不是手误。

> 顺带一个 Python 陷阱：`bookends.py` 里片尾署名原本是隐式字符串拼接
> （`f'…{{\\pos(...)}}'` 换行接下一个字面量）。把第二个字面量换成 `E.END_LINE` 之后
> 变成「字面量 表达式」相邻，语法错误。替换这种位置要补 `+`，并且改完立刻
> `python3 -m py_compile` 一遍——这类错误只在真正跑到那一行时才炸。

## 删掉「说了的话」要另立一张表，断言方向和删死气相反

用户点名要删的内容，和工具出故障的死气，是两件事，用两张表记：

| 表 | 删什么 | 断言 |
| --- | --- | --- |
| `EXCISE` | 画面在动，但动的是故障 | 区间内**不含人声** |
| `CUT_SPEECH` | 用户点名不要的内容 | 内部允许人声，**两端必须落在静音里**（±20ms 内峰值 ≤ 门槛） |

**不要为了少一张表去放宽 `EXCISE` 的断言。** 那条断言是「不小心切掉一句话」的唯一防线，
而「不小心切掉一句话」和「决定切掉一句话」在成片里听起来完全一样——只有表能区分，成片
不能。合成一张的那一刻，下一期照抄这张表就会静默吃掉一句话。

删有声内容前先找重述：EP.03 那段（源 109.3–121.4s）能删只因为素材尾部 131.4s 他又讲了
一遍完整的。同时看它挨着谁——那一刀正好接上已有的故障切除段，两段连成一刀，比夹在一句话
两半中间好。

## 字幕要按「这句话在成片里还听得到吗」过滤

`to_out()` 把源时间映射到成片时间，而它对**已被移除**的源时间只能返回切点。于是一条整段
被删的 cue 不会消失，而是塌到切点上，再被「停顿被剪掉的 cue 仍要读得到」那条 0.40s 兜底
撑开——**字幕在讲片子里没有的话**。EP.03 上一版交付就有 14 条，删掉一段后又多出 5 条，
四行叠在同一个 0.40s 窗口里。

判据是**这条 cue 与保留下来的人声段有没有重叠**，下限 0.05s（比一个音节还短）：

```python
SPEECH = {}                                   # 只收 type == 'speech' 的段
for s in MAN['segments']:
    if s['type'] == 'speech':
        SPEECH.setdefault(s['src'], []).append((s['src_in'], s['src_out']))
```

**不能用「有没有落在某个段里」**：空档段的音频被换成了底噪，字幕落在那里同样无声。

烧进画面的字幕和交付的 SRT 必须共用这一份判据（`export_srt.py` 直接 `import build_subs`），
两边各判一次就会对不上，而对不上的方式是安静的。丢弃条数要打印出来、写进交付报告——
掉了东西不说，和没掉一样看不出来。

## 钩子出点：探针会漏掉比它粒度还短的句界

10ms 包络是给「找静音段」用的，不是给「找句界」用的。EP.03 的「跑通了」和「所以我们用
第三方的平台」之间只隔着一段 **70ms 的辅音谷**：2ms 粒度实测最低 −51.6 dBFS，而同一处的
10ms 窗被平均成 −47.9，高于 −50 门槛，探针于是越过这个句界一路走到下一句中间——这就是
「钩子没读完就切」的成因，而它看起来完全像是「探针找到了一个静音点」。

处置是留一张**出点覆盖表**（`OUT_FIX`），并且只准以一个理由写入：句界比包络粒度还短。
写之前按 2ms 粒度量一遍，量不出低谷说明那里根本不是句界。覆盖值不要从转写抄——转写的
cue 边界本身就不可靠——而要用转写**反向验证**：把候选出点两侧各切一段送 ASR，读出来
正好是两句完整的话，出点才算定了。

```bash
ffmpeg -v error -y -ss 530.80 -t 1.90 -i src.wav -ar 16000 -ac 1 /tmp/a.wav
whisper-cli -m ggml-large-v3-turbo-q5_0.bin -l zh --no-prints -nt /tmp/a.wav
```

顺带两个坑：`whisper-cli` 的 `-ml 1` 不一定给出词级切分（会退回整块），别指望它；
zsh 里 `set -- $spec` **不做词分割**，循环里批量切片会静默地反复读同一个临时文件，
三段转写出一模一样的结果。

## 成片路径和版本号也只准有一处

`episode.py` 收口的不只是文案。EP.03 还踩到两处：

- `timeline_check.py` 自存了一份 `render.py` 里 `OUT` 的副本。改了成片名，质检会去
  ffprobe **上一版的文件**，然后所有项报绿。凡是要指向成片的地方都从 `render.py` 读：
  `[ln.split("'")[1] for ln in open(f'{WORK}/render.py') if ln.startswith('OUT = ')][0]`
- 剪辑版本号在交付报告里是字面量，于是文件名停在 `v0.1`、报告写着「成片 v0.2」。版本进
  `episode.py`（`CUT` / `COVER`），报告插值。

**成片文件名不要每轮改。** 交付路径一轮换一次，上一版就成了孤儿文件，而「我要验收哪个」
这种问题不该由文件名回答——版本号在报告里说，路径保持稳定。

## 《川言川语》EP.01（纯口播观点短片）新增的踩点

这一期没有屏幕舞台：一条 1920×1080 的横向近景自拍，从头到尾只有人脸和字幕。
录屏系列的多数判据在这里失效，另外几条则第一次被逼出来。

- 横向近景自拍不要满屏裁 9:16：先量人头宽（本期 780px），9:16 从 1080 高只能裁出 607px，裁下去先切耳朵；改「6:5 中景 + 同源虚化底」（2026-09-09, b1e137e）
- 虚化底必须压到 brightness≈-0.42：底图跟着素材走，同一条片子会从近黑桌面切到亮灰天花板，-0.20 时陶土色系列名在亮灰上读不出（2026-09-09, b1e137e）
- 纯口播片没有「有动作的停顿」这个例外，所有 ≥0.30s 的气口都可压；保留头 60% / 尾 40%、只挖中间，接缝仍是一处，上一句的衰减和下一句的起音都完整（2026-09-09, b1e137e）
- 切点门禁要「绝对够静 + 比邻近 0.4s 峰值低 18dB」两条一起判：只用绝对门槛会漏掉整段本来就轻的位置，只用相对门槛会在长静音里到处判通过（2026-09-09, b1e137e）
- 删除表里的端点不许从 DTW token 时间抄：本期 86s 一带 DTW 整体偏 0.3s，照抄会把「所有人的」的尾巴切进去；端点一律从 10ms 包络的局部低谷量（2026-09-09, b1e137e）
- whisper 的第一个 segment 一律从 0.00 起算：本期真正的第一个字在 2.35s，字幕照抄会整条提前两秒多（2026-09-09, b1e137e）
- cue 边界吸附要吸到**语音段边界**，不是「窗内第一个有声采样」：后者会把终点拉到下一句的尾巴上，字幕覆盖率从 78s 涨到 93s，看着像更完整，其实每条都伸进了下一句（2026-09-09, b1e137e）
- 吸附还要用邻居的原始边界夹住，否则相邻两条短句会互抢同一个语音段，随后触发「相邻 cue 不许重叠」的断言（2026-09-09, b1e137e）
- 产品名只要 ASR 四次一致仍读不通（本期「Workbody」实为 WorkBuddy），就问用户，不要用提示词硬掰——错的产品名会同时进字幕、标题和发布文案（2026-09-09, b1e137e）
- `ffmpeg` 的 `-fps_mode passthrough` 和 `-r` 不能同时给（"contradictory"）；用 `select+setpts` 时直接省掉 `-r`（2026-09-09, b1e137e）
- 渲染命令不要带 `-stats`：日志会灌满逐帧进度，后续 `tail` 一次就吃掉几千 token（2026-09-09, b1e137e）
- 卡片是独立片段，只有卡片文案变了时可以只补渲卡片再重新 concat；前提是 `edit-manifest.json` 逐键与上一版一致（2026-09-09, b1e137e）
- `lov-channels-cover` 只出 3:4 / 4:3 两个视频号槽位，B 站的 16:9 是**另一个槽位**不是它缺一档；16:9 在本期自排，但色板、字族、图层顺序照抄它锁定的设计系统（2026-09-09, b1e137e）
- 封面钩子写「最贵的」之前先回片子：本期口播只说过「最好的」，没说过「贵」，钩子跟着改成「越该用最好的」才有画面证据（2026-09-09, b1e137e）
- 短片（<2 分钟）默认不做冷开场：本期高光 7.1s + 片名卡 2.2s 占了 108.6s 的 9%，等于用 9% 的时长介绍剩下的 91%；`direct` 应该是短片的默认，`highlights` 才需要理由（2026-09-09, 07d181e）
- 片头片尾要能整段关掉，不能留 0 长度占位：帧数为 0 的段在下游会被当成"存在但很短"，接缝、音频拼接和 cue 映射都会按存在处理（2026-09-09, 07d181e）
- 后台守候脚本里不要写裸 glob：zsh 对 `subs-approved-*.srt` 无匹配时直接报 `no matches found` 并让整个循环退出，守候看起来"启动成功"却在第一轮就死了；改用 `find . -maxdepth 1 -name '...'`（2026-09-09, 07d181e）
- 「片子短所以不做片头」不是判据，**正片第一句能不能当钩子**才是：本期第一句「跟大家分享一个…非共识」只报体裁不给内容，砍掉片头后作者比较两版判定「不如有那个片头的」，v0.3 又装回去（2026-09-09, 42a9ebb）
- 发布大节点表不能按「锚点非空」过滤：冷开场那条的锚点本来就是 None（它不在正片时间轴上），一过滤 00:00 那个节点就静默消失，而节点表读起来仍然自洽（2026-09-09, 42a9ebb）
- zsh 下 `rm -f a_* b_*` 只要有一个模式无匹配，整条命令都不执行（不是跳过那一个）；批量清理用 `find ... -delete`（2026-09-09, 42a9ebb）
